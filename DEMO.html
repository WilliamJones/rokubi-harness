i.The demo project

One real bug, hiding in plain sight

demo-project/ is a tiny cart with five tests. Four pass. One fails — and the bug is the kind that survives code review: the discount is applied to every line instead of once to the order.

Percentages hide it completely, because percentages are distributive: 10% off each of £80/£20/£40 is the same £126 as 10% off £140. Only a fixed discount exposes it — £20 off a three-line order takes £60.

iii.The evidence

It ends with a receipt, not a claim

A chat assistant finishes by saying “I’ve fixed it.” The harness finishes with what it changed, what it actually ran, and a way back. It also marks what it didn’t verify — it never claims a check it didn’t run.

the edit it made — src/cart.js (real diff)
 export function total(items, discount) {
-  // BUG: the discount is applied to each line, then summed. It should be applied
-  // once, to the subtotal.
-  const discounted = items.map((item) =>
-    applyDiscount(item.price * item.quantity, discount),
-  );
-  return round(discounted.reduce((sum, line) => sum + line, 0));
+  return round(applyDiscount(subtotal(items), discount));
 }

Undo Task restores every file the task touched to exactly how it started — checkpointed before each edit, independent of Git, so it works even in a folder that isn’t a repository. Click it and the bug comes back.

iv.Your turn

Do it yourself in two minutes

  1. Open the demo project. Build and launch the app from your clone with scripts/bootstrap.sh (once) and scripts/run.sh, press ⌘O, and choose demo-project. It ships broken on purpose.
    # confirm the bug is there first cd demo-project && npm test # → 4 pass, 1 fail
  2. Pick a model that can drive tools. Click Choose Model in the toolbar and search. Your choice is remembered next time. anthropic/claude-sonnet-* or openai/gpt-5* are reliable; free flash/mini/XS tiers will just chat at you and never run anything.
  3. Set Autonomy to Full Autonomy so it can run the tests without stopping to ask.
  4. Type four words: Fix the failing test. then ⌘↩. Don’t tell it which file — finding that out is its job.
  5. Watch, then check. When the receipt appears, hit Review Changes for the diff, then Undo Task — and run npm test again to see the failure return.
If it just chats at you

That’s the model, not the harness — a weak model never calls the tools. Switch to a stronger one and send the same four words again.

v.The difference

What you just watched

Four things happened that a chat sidebar structurally cannot do — and one thing that didn’t.

  1. It reproduced the bug before touching code. The first thing it ran was your test suite, so it was working from evidence, not a guess.
  2. It edited real files and re-ran the suite. Edit → test → verify, on its own, until green.
  3. It reported honestly. “5 tests passed” is a fact it observed; the lint row says not run because it wasn’t.
  4. All of it is reversible. One click puts every file back, no Git required.
  5. And the interface stayed out of the way. The terminal, plan, and problems panels appeared only while they were useful, then collapsed. That’s the design principle — the harness is as simple as the task allows, and no simpler.

Give it a goal. Check its receipt. Undo it if you disagree.
