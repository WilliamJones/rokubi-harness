1.Start here

Install and launch

You need macOS 15 or later, Xcode 26, and Node.js with npm. The app is built and tested on Apple Silicon.

Terminal check your tools

sw_vers -productVersion # 15.0 or later xcodebuild -version # Xcode 26 node --version && npm --version

Terminal download, build, and open the app

git clone https://github.com/WilliamJones/rokubi-harness.git cd rokubi-harness scripts/bootstrap.sh # once: installs XcodeGen and the editor's dependencies scripts/run.sh # builds a Debug copy and opens it

Terminal install a Release copy in Applications

scripts/package.sh --install open /Applications/RokubiHarness.app
Keychain prompt

Builds are signed locally, so macOS treats each new build as a new app. The first launch after a rebuild asks to use your saved keys. Click Always Allow.

3.Start here

Open a project

A project is any normal folder. There's no import step.

  • Open Folder… in the welcome window, or press ⌘O any time.
  • Drag a folder onto the welcome window.
  • Click a project under Recent. Right-click one to Remove from Recents. The list keeps the last 12.
  • File › Open Recent lists the same projects, with Clear Menu at the bottom.

Each project opens in its own window. The app keeps running after you close the last window.

Terminal open a project, or a project and a file, from the command line

open -n /Applications/RokubiHarness.app --args --project ~/code/my-app open -n /Applications/RokubiHarness.app --args --project ~/code/my-app --open src/index.ts
Known issue

Open Folder… in the command palette only adds the folder to Recent. Use ⌘O to open it.

7.The workspace

The editor

The editor is Monaco, the engine inside VS Code. Everything the agent writes, you can edit by hand.

  • Tabs: a dot (●) means unsaved changes. Hover a tab to see its close button.
  • Saving: there's no autosave. Press ⌘S, or ⌥⌘S to save everything.
  • Languages: picked from the file extension. TypeScript, JavaScript, JSON, CSS, SCSS, Less, and HTML get full autocomplete and error checking. Other languages get syntax colouring.
  • Multiple cursors: hold ⌥ and click.
  • Every Monaco command: press ⇧⌘P inside the editor.
Save before closing

Closing a tab doesn't ask to save. Unsaved edits in that tab are lost. Press ⌘S first.

Autonomy: how much the agent may do

Set it from Autonomy ▾ in the chat header. It starts at Standard and is remembered for every project.

Answering an approval request

When an action needs approval, a card appears in the chat: "<agent> wants to <action>", with the exact command or path underneath.

Allow Return
Run this one action.
Always Allow
Allow similar actions until this task finishes. For commands it remembers the first word: approving npm test allows any npm … command. A command that starts with a path, like ./scripts/test.sh, is remembered exactly.
Deny Esc
Block it. The agent is told and tries another way.

"Always" resets with your next message. To allow something for good, add a rule to .rokubi/permissions.json. A few dangerous commands are blocked at every level; see Hard limits.

Attach context with @

Type @ in the chat box to see suggestions. Press Tab to accept the first one. Attached items show as small chips under your message.

@problemsEvery entry in the Problems list.

@src/What's inside that folder, one level deep.
@src/cart.jsThe whole file, up to 40,000 characters. Secret files are skipped.

Paths are relative to the project folder and must match exactly, so use the suggestions. A mention that matches nothing is ignored without a warning.

11.Working with the agent

Skills: reusable prompts with /

A skill is a saved prompt. Type / at the very start of a message to see them, then Tab to pick one. You can also choose one in the command palette. Anything you type after the skill name is added to its instructions.

Built-in skills

SkillWhat it does
/reviewReview the current changes for bugs and risks
/testRun the project's tests and fix failures
/refactorRefactor the selected code or named module without changing behaviour
/explainExplain how part of the project works
/security-reviewAudit the changes or project for security issues

Chat

/explain how checkout calculates the total

Chat

/security-review @changes

Make your own

  • A skill is a Markdown file. The file name, without .md, is the skill name, so use no spaces.
  • The first line, without the #, is the description shown in suggestions.
  • The whole file is sent, then a --- line, then whatever you typed after the name. Don't add YAML front matter; it's sent as plain text.
  • Put team skills in .rokubi/skills/ inside the project. Put personal skills in ~/.rokubi/skills/. Project skills win over personal ones, and both win over built-ins with the same name.
  • New skills appear within a couple of seconds, or as soon as you open the command palette.

Terminal run in your project folder: a team skill

mkdir -p .rokubi/skills cat > .rokubi/skills/changelog.md <<'EOF' # Draft a changelog entry for the current changes Run git_diff and git_log (limit 10). Write an entry under "## Unreleased" in CHANGELOG.md, grouped as Added / Changed / Fixed, one line per change, in user-facing words. Only edit CHANGELOG.md. Finish with report_completion. EOF

Chat

/changelog

Terminal a personal skill for every project

mkdir -p ~/.rokubi/skills cat > ~/.rokubi/skills/add-tests.md <<'EOF' # Add unit tests for the file I name Read the file I name and the existing tests next to it, and match their style. Add focused tests for untested branches and edge cases. Run the test command until it passes. Do not change production code. Finish with report_completion. EOF

Chat

/add-tests src/cart.js

That last message sends the skill's text, a --- line, and then src/cart.js. A /name that matches no skill is sent as ordinary text.

12.Working with the agent

AGENTS.md: instructions for every message

Put an AGENTS.md file in the project root, and the agent reads it on every message. Only the root file is used, and only its first 12,000 characters. List the exact build and test commands, so the agent verifies its work the way you do.

Terminal run in your project folder, then edit to match your project

cat > AGENTS.md <<'EOF' # Project instructions ## Commands - Install: `npm ci` - Test: `npm test` - Lint: `npm run lint` - Type-check: `npx tsc --noEmit` ## Conventions - TypeScript strict mode. No `any`. - One component per file in `src/components/`. - Money is stored as integer cents. ## Don't - Don't edit generated files in `src/generated/`. - Don't add dependencies without asking. EOF

Pair this with permission rules that allow those same commands, and the agent can verify without stopping to ask.

13.Working with the agent

Conversations

Conversations belong to the project and save automatically. When you open a project, its newest conversation opens with it.

  • Switch or start one: click the menu at the top left of the chat panel, labelled with the assistant's name. It lists New Conversation and your 15 most recent conversations. The menu is disabled while the agent is working.
  • Titles come from the first line of your first message.
  • Stop the agent with ⌘. or the stop button. The chat shows "Stopped."
  • Tokens used appear under the chat box.
  • Switching models mid-conversation adds a note saying which model wrote the earlier replies.

There's no delete button yet. Conversations are JSON files; see Where things are stored.

19.Review and undo

Checkpoints and undo

One message you send is one task. Before the agent edits, creates, renames, or deletes a file, the app saves a copy. This works even in folders that aren't git repositories.

Undo Task
Restores every file the task touched and removes files it created. Find it on the completion card, in the command palette, or as Reject All in the review.
Reject File
Restores one file, from the review.
Revert
Restores one change inside a file, from the review.
What undo can't bring back

Changes made by commands the agent ran, like npm install or a code formatter. Folder renames and deletes. Your own edits. Undo works only for the latest task in the window, and switching conversations clears it. Files the agent deleted also sit in the Finder Trash.

For big tasks, give yourself a git safety net first.

Terminal before a big task

git add -A && git commit -m "Checkpoint before agent task"

Terminal set the agent's attempt aside, keeping it recoverable

git stash push -u -m "agent attempt" git stash list # bring it back later with: git stash pop
20.Review and undo

Git

The agent's git tools can read git status, git diff, and git log. Anything else, like committing, has to go through a terminal command, which your autonomy setting controls. Force pushes are always blocked. The app doesn't show the current branch.

Commit stages everything

Commit on the completion card, and Git Commit… in the palette, run git add -A. That includes your own unrelated changes. The commit message is the first line of the task summary. There's no confirmation step.

Chat

Terminal commit only the files you choose

21.Rules and safety

Permission rules: .rokubi/permissions.json

This file sets rules for one project. It's read every time you send a message, and it can live in your repository so the whole team shares it. It's a JSON list. Each rule has a class, an optional match, and a decision.

classCoversmatch is compared with
runTerminal commandsThe whole command line
editEditing, rewriting, and renaming filesThe file path
createCreating filesThe file path
deleteMoving files to the TrashThe file path
readReading and listing filesThe file path
searchFinding files and searching contentsRules without a match only
gitReadgit status, diff, and logRules without a match only
  • decision is allow, ask, or deny.
  • match for run: * matches anything, including spaces and slashes. npm test* matches npm test -- --watch.
  • match for paths: paths are relative to the project. * stays inside one folder, ** crosses folders, and {a,b} means either.
  • No match means the rule covers every action in that class.
  • Order: the always-blocked list, then this task's Always Allow answers, then this file, then your autonomy setting. Inside the file, the last matching rule wins.
Silently ignored

A rule that says allow with no match is dropped for anything beyond reading and searching, so a cloned repository can't give itself free rein. And if any rule has a typo, like "Run" instead of "run", the whole file is ignored.

Terminal Node project: run tests, lint, and type-check without asking

mkdir -p .rokubi cat > .rokubi/permissions.json <<'EOF' [ {"class": "run", "match": "npm test*", "decision": "allow"}, {"class": "run", "match": "npm run lint*", "decision": "allow"}, {"class": "run", "match": "npx tsc --noEmit*", "decision": "allow"} ] EOF

File .rokubi/permissions.json for a Swift package

[ {"class": "run", "match": "swift build*", "decision": "allow"}, {"class": "run", "match": "swift test*", "decision": "allow"} ]

22.Rules and safety

Hard limits and secrets

Always blocked, at every autonomy level

  • Force pushes: git push with --force, --force-with-lease, -f, or a +branch.
  • rm aimed at /, ~, or $HOME.
  • sudo and doas.
  • Formatting disks with mkfs, writing to raw disks with dd or > /dev/disk…, and chmod -R 777 / or chown -R … /.
  • The shell fork bomb.

Ordinary commands like rm -rf node_modules are not blocked. This list is a backstop, not a sandbox: commands run in your real login shell.

Secret files

The agent can't read, edit, search, rename, or delete files named .env, .env.*, *.pem, *.key, *.p12, credentials.json, id_rsa, or id_ed25519. Every path must stay inside the project, even through symlinks.

Gaps to know about

Secret file names still show up in file listings. git diff shows the contents of secrets you've committed. A terminal command like cat .env can read them if you allow commands. On repositories you don't trust, stay on Standard or Ask Before Commands.

What the agent skips when searching

File listings, search, and the project map skip node_modules, .build, DerivedData, dist, build, target, .venv, __pycache__, .next, coverage, Pods, and similar folders, plus your root .gitignore. The agent can still open one of those files if it names the exact path.

Troubleshooting

ProblemFix
The agent just chats and never runs anythingThe model can't call tools well. Pick a stronger one and send the same message again.
A Keychain prompt after every rebuildExpected for locally signed builds. Click Always Allow.
"Port 1455 is already in use"Another sign-in window is open. Close it, or find what's using the port with the command below.
"The ChatGPT account has no account id; is a workspace selected?"Choose a workspace in ChatGPT, then sign in again.
An error on the first message after pasting a keyThe key is wrong. Open ••• › Sign Out and connect again.
A command "timed out"Ask for a longer timeout, up to 900 seconds, or run it yourself in Terminal.app.
My permission rules do nothingCheck the JSON is valid and every class is spelled exactly. A blanket allow is ignored. Paths are relative to the project.
No Problems chipOnly commands the agent runs are scanned, and only in the formats listed under Problems.
@file attached nothingThe path must match exactly, relative to the project. Secret files are skipped.
A new skill doesn't show upIt must be a .md file directly inside the skills folder, with no spaces in its name. Open ⌘K to refresh.
Undo Task didn't restore somethingUndo doesn't cover changes made by commands. Use git; see Checkpoints.
My unsaved edits vanishedClosing a tab doesn't ask to save. Save with ⌘S before closing.
Open Folder… in the palette doesn't open anythingKnown issue. Use ⌘O.

Terminal see what's using the sign-in port
