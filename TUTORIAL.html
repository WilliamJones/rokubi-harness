Native macOS · Field Guide

A visual control surface for an autonomous software engineer.

ROKUBI Harness gives ChatGPT a goal, then shows you the work: the files it reads, the commands it runs, the diffs it writes, and the evidence that it’s done. This guide walks every surface, from the three‑pane home to the completion card.

i.The surface

The default workspace

Open a project and the window shows three things and nothing more: your files on the left, the editor in the middle, and ChatGPT on the right. That’s the whole interface until a task needs more of it.

Terminal output, plans, diffs, problems, and Git actions all exist — they just stay out of the way and surface contextually, then recede when the task is done. A capability has to earn permanent space through frequency and necessity.

ii.The surface

Opening a project

From the welcome window, Open Folder (⌘O), pick a recent project, or drag a folder onto the window. The harness works directly on a normal local folder — there’s no import step and no proprietary project format.

File tree
Hierarchical, lazy‑loaded, and .gitignore‑aware — build output and dependencies stay hidden.
Live updates
A filesystem watcher keeps the tree and open files current. Edit by hand any time; the agent notices changed files before it continues.
File actions
Create, rename, move, duplicate, delete, and drag‑and‑drop, all from the Explorer’s context menu.
iii.The surface

The editor

A full code editor (Monaco) sits at the centre — the same engine as VS Code. It’s a real editing surface, not a read‑only preview: everything the agent writes, you can refine by hand.

Editing

Syntax highlighting, tabs, code folding, bracket matching, multiple cursors, autocomplete, and formatting.

Commands

Find & replace (⌘F), format document, toggle comment (⌘/), go to line (⌘L), and save (⌘S).

Human first

If a file changes on disk while you have unsaved edits, the editor tells you and lets you Reload or Keep Mine — your work is never silently overwritten.

iv.The conversation

Intent comes from the conversation

There are no Ask / Plan / Edit / Agent buttons to choose between. You just say what you want, and the harness reads your intent from the words:

“Explain…”
It reads the relevant files and explains.
“Plan how…”
It investigates and produces a short plan.
“Do it.”
It edits.
“Fix the tests, keep going until they pass.”
It edits, runs, diagnoses, fixes, and verifies.

Conversations belong to the project and persist between sessions. Start a fresh one or reopen an earlier thread from the ChatGPT ▾ menu at the top of the panel.

v.The conversation

The one dial that matters: authority

Instead of behavioural modes, the harness has a single persistent control — how much authority you grant the agent. Set it from Autonomy ▾ in the chat header.

READ ONLY

Read Only

Can inspect, search, and read Git status — but cannot modify anything.

STANDARD

Standard

Reads, searches, and edits freely. Destructive or external actions ask first.

ASK CMDS

Ask Before Commands

File edits proceed on their own; running terminal commands needs your approval.

FULL

Full Autonomy

Runs edit → test → fix → verify without stopping — still inside hard security limits.

Whatever the setting, a small set of dangerous actions is always blocked (see Permissions).

vi.The conversation

Point at things with @, run workflows with /

Attach context with @

Type @ in the composer to hand the agent exactly what it needs — nothing more loads by default, keeping the context small and the work fast.

@path/to/file
A file or folder’s contents.
@selection
Whatever is highlighted in the editor.
@terminal
Recent terminal output.
@problems
The current diagnostics.
@changes
Files changed in this task.

Skills with /

A skill is just a Markdown file in .rokubi/skills/ (or ~/.rokubi/skills/). Type / to run one — its instructions are prepended to your message. Skills are how you add higher‑level workflows like /review or /deploy without cluttering the interface.

vii.The work

What the agent can actually do

Every action goes through a structured tool — the model never gets raw access to your machine. The tools compose a few primitives: read, search, edit, create, delete, run.

read_fileRead a file, by line range
list_dirList a directory
globFind files by name pattern
grepSearch file contents (regex)
apply_patchPrecise search/replace edits
write_fileReplace a whole file
create_fileMake a new file
rename_pathMove or rename
delete_pathMove to Trash
run_commandRun a shell command
git_status / diff / logInspect the repository
update_planShow a step checklist
report_completionClose out with evidence
Secrets are off‑limits

The agent can never read files like .env, *.pem, *.key, or credentials.json, and every path is checked to stay inside the project root.

viii.The work

Permissions, only when needed

Each tool falls into a permission class, and your autonomy preset (plus any custom rules) decides whether it’s allowed, asks first, or is denied. Approvals appear inline in the chat — never a modal that stops everything.

Allow
  • read files
  • search
  • git status
  • npm test
Ask
  • install packages
  • delete files
  • git commit
  • network access
Deny
  • force push
  • rm -rf /
  • sudo
  • disk writes

When the agent asks, you can Allow once, Always Allow that kind of command for the session, or Deny. Project‑level rules live in .rokubi/permissions.json; the deny list of genuinely dangerous commands holds regardless of autonomy.

ix.The work

Watching it work

Instead of a wall of narration, the agent’s actions appear as compact, collapsible activity rows inline in the conversation. You see what happened; you expand only what you want the detail on.

✓ Searched project for “theme”
✓ Read 5 files
✓ Edited src/theme.ts
▸ Ran npm test — 48 passed

For multi‑step work the agent can post an Implementation Plan that ticks off as it goes. Simple tasks get no plan at all — planning is a contextual artifact, not a permanent panel.

x.The work

The terminal

Hidden until something runs, the terminal drawer opens under the editor the first time you — or the agent — run a command. It’s a real PTY running your login shell, so PATH, nvm, and everything else behave exactly as in Terminal.app.

Who ran it
Commands the agent runs carry a ⚡ badge; yours don’t. Open your own shells with ⌃`.
Jump to code
Any path:line in the output is clickable — it opens that spot in the editor.
Agent‑readable
Output is captured (ANSI stripped) so the agent can read results and keep going.
xi.The work

Problems

When a build, type‑check, lint, or test run reports errors, a ⚠ Problems chip appears beneath the editor. The harness parses output from tsc, eslint, swiftc, cargo, pytest, and jest/vitest into a real list.

Each problem opens its exact location in the editor (with an inline marker), and any problem — or the whole list — can be handed straight to the agent with Fix with ChatGPT.

xii.The evidence

Changes & visual diffs

After the agent edits files, a 4 files changed  Review chip appears. Review opens a focused side‑by‑side diff — the file’s state when the task began on the left, the current version on the right.

Accept
Keep a file’s changes, or accept all.
Reject
Revert a file to its pre‑task state, or reject all.
Edit
The diff is editable — tweak the result by hand before you accept it.
xiii.The evidence

Checkpoints & undo

Before every mutating action, the harness snapshots the file. That makes the whole task reversible — independently of Git, so it works even in a folder that isn’t a repository.

Undo Task
Restore every file the task touched to how it started.
Revert file
Roll back a single file from the diff view.
Undo last action
Step back one mutating step at a time.
xiv.The evidence

Git, when it’s relevant

Git is a first‑class capability but not a permanent sidebar. The agent can read status, diff, and log; the current branch shows in the title bar; and once you’re happy with a task, Commit stages and commits it straight from the completion card. Committing stays a human decision.

xv.The evidence

Autonomy that ends in evidence

For implementation work the agent runs a loop, not a single shot — and it doesn’t just claim success, it shows it.

edit→ build / lint→ test→ inspect failure→ fix→ verify

Every meaningful completion answers three questions — what changed, what was verified, and can I undo it — in a single card:

TASK COMPLETE

Dark mode implemented using the existing design tokens.

Changes
4 files changed
Verified
TypeScript
Lint
14 tests passed
Production build

The card is honest about its reach: it distinguishes what was implemented, compiled, linted, and tested from what was not verified — it never claims a check it didn’t run.

xvii.Getting around

Project memory: AGENTS.md

Drop an AGENTS.md in your project root and the harness always loads it as context — architecture notes, conventions, preferred libraries, forbidden patterns, the commands to build and test. It’s the “files before subsystems” principle in practice: a plain file, not a settings screen.

xviii.Getting around

Accounts & models

Sign in three ways, all behind the same interface:

Sign in with ChatGPT
Uses your ChatGPT Plus/Pro account (OAuth). Tokens live in the macOS Keychain and refresh on their own.
OpenRouter
One key, hundreds of models from OpenAI, Anthropic, Google, Meta, Mistral and more. The harness speaks OpenRouter’s universal Chat Completions API, so any model in its catalog works.
OpenAI API key
Paste a platform key instead — also stored in the Keychain.

Finding a model

Click the model name in the title bar to open a searchable picker: fuzzy‑search by name or id, and see each model’s context length and price per million tokens before you choose. ⌘K → Change Model works too.

Simple when the task is simple; more powerful only as the task grows.

For contributors: build with scripts/build.sh, test with scripts/test.sh, launch with scripts/run.sh. To exercise the agent loop offline, point a debug build at the bundled mock:

# drive the full tool loop with no network RokubiHarness --project ./demo \ --base-url http://127.0.0.1:8765 --api-key test \ --prompt "Add a greeting line and verify"
